# Фронтенд eShop

Адаптивный интерфейс на HTML, CSS и JavaScript без сборщика и npm. Файлы находятся в `wwwroot`. ASP.NET Core раздаёт их с того же адреса, что API; CORS не нужен.

## Запуск

1. Установи .NET 10 SDK и запусти PostgreSQL.
2. Настрой существующие User Secrets проекта: `ConnectionStrings:ConnectionPostGre` и `ApiKey:JwtSecretKey`. Секрет JWT для HS256 должен быть не короче 32 байт. Не добавляй секреты в Git.
3. Примени миграции: `dotnet ef database update` (требуется инструмент dotnet-ef).
4. В папке с `eShop.Api.csproj` выполни `dotnet run --launch-profile http`.
5. Открой http://localhost:5136. Не открывай index.html двойным щелчком и не запускай через Live Server: запросы API рассчитаны на один origin.

## Возможности

- Каталог из GET /products/, поиск по имени и описанию, сортировка, фильтр цены и доступности.
- Избранное хранится в браузере (localStorage), без аккаунта.
- Регистрация и вход с именем, email и паролем согласно текущему API.
- JWT хранится в sessionStorage; авторизованные запросы отправляются с Bearer-токеном.
- Профиль GET/PUT /users/me; после изменения требуется повторный вход.
- Создание, редактирование и удаление товаров. Удаление подтверждается в диалоге.
- Кнопки редактирования показаны владельцу или Admin. Окончательную проверку прав делает сервер.
- Загрузка, пустые результаты, ошибки сети, ошибки валидации и истёкшая сессия обработаны.

## Настройки

В `wwwroot/config.js`: валюта по умолчанию UAH (сам API валюту не содержит), locale ru-RU, apiBase пустой для одного origin. Чтобы сменить валюту, измените currency. Для другого origin API потребуется настроить CORS на сервере отдельно.

В API описание называется **Decription**, поэтому клиент отправляет **decription**, сохраняя контракт. Вход требует одновременно username, email и password. Валидаторы пароля фактически требуют 5–30 символов; frontend следует этой проверке.

Фотографий, категорий, заказов, оплаты и контактов продавца в API пока нет. Для настоящих товаров используются нейтральные SVG-заглушки. Демонстрационные иллюстрации и товары не выдаются за данные сервера.

## Демо

Добавь `?demo=true` к адресу сайта. Демо явно помечено; данные существуют в памяти вкладки. Кнопка «Войти» позволяет попробовать демо-продавца без настоящего пароля. Избранное сохраняется отдельно от сервера. Реальный режим никогда автоматически не подменяет ошибку API демонстрационными товарами.

## Изменения бэкенда

- `Program.cs`: UseDefaultFiles и UseStaticFiles для wwwroot.
- `validators/product_validator.cs`: UpdateValidator для PutProductDTO. Без него существующий PUT endpoint не может получить IValidator<PutProductDTO> из DI.

## Проверки

`node --test tests/api.test.mjs` — контракт запросов, JWT, пустые ответы, ошибки сети/валидации, 401. Node нужен только для этих проверок, не для работы сайта.

В среде создания проверены синтаксис JavaScript и API-клиент на подставных HTTP-ответах. Полный запуск .NET/PostgreSQL и визуальная проверка браузером не выполнены: в среде нет .NET SDK и доступного браузерного инструмента Sites.

Перед публичным запуском отдельно исправьте существующий GET /users/: сейчас он возвращает User целиком, включая HashPassword. Фронтенд этот endpoint не использует. Для безопасного ответа можно проецировать записи в уже существующий GetUserDTO.
